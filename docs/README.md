# run_qemu-based Jenkins jobs

A family of Jenkins jobs that build a famfs kernel and boot it under
[`run_qemu`](https://github.com/pmem/run_qemu) to run tests in a VM. They share
one reusable Pipeline fixture and one build agent.

## What each job tests (code under test)

All four build and boot the **`linux.git@famfs`** kernel
(`/home/jenkins/git/linux.git`, config `configs/famfs_qemu_ndctl.config`); they
differ in the user-space code they exercise:

| Job | Code under test | Tests run | Status / gating |
|-----|-----------------|-----------|-----------------|
| [`ndctl_qemu_test_famfs_local`](ndctl_qemu_test_famfs_local.md) | **`jagalactic/ndctl@famfs`** | daxctl famfs mode-transition (`daxctl-famfs-{nfit,cxltest}.sh`) | green; red on failure |
| [`ndctl_qemu_test_all_local`](ndctl_qemu_test_all_local.md) | **`jagalactic/ndctl@famfs`** | full ndctl meson suite (`ndctl`+`dax`+`cxl`) | UNSTABLE on test fail, red on infra |
| [`smoke_qemu_nfit_local`](smoke_qemu_nfit_local.md) | **`famfs.git@master`** user-space | `run_smoke.sh` (fuse + v1) + unit tests, on an nfit_test devdax | **green**; red on failure |
| [`smoke_qemu_cxltest_local`](smoke_qemu_cxltest_local.md) | **`famfs.git@master`** user-space | same, on a `cxl_test` (mock) devdax | experimental; **does not pass** - 512 MiB cxl_test region vs 4 GiB famfs minimum (see job page for options) |

Sources are **local mirrors on thing1** (`/home/jenkins/git/`), maintained by
pushing to them; branches are hardcoded in each entrypoint. See each job's page
for the exact source/ref table.

## Build agent

All jobs run on the node **`thing1`**, label **`run_qemu`**:

- thing1 is the NFS *server*, so its `/home` is **local disk** (NFS clients lack
  xattr, which breaks mkosi — see the agent's local-disk workspace).
- Inbound JNLP agent (`jenkins-agent.service`), `jenkins` user, **4 executors**.
- In the `kvm` group + passwordless `sudo`. Toolchain: OpenJDK 21, mkosi 25.x,
  qemu/KVM, dracut, argbash, OVMF, zstd.
- Source mirrors live at `/home/jenkins/git/{linux.git, famfs.git}`.

## Shared fixture: `run_qemu_fixture.groovy`

`load`ed by each job's entrypoint inside a `node('run_qemu') {}` block. It:

1. Clones/updates the **run_qemu fork** (see below) and the kernel tree.
2. Drops in the saved `.config` and `make olddefconfig`.
3. Runs `run_qemu` (kernel build -> mkosi rootfs -> boot -> `--autorun`),
   passing `--instance ${EXECUTOR_NUMBER}` (concurrency-safe ports/MACs) and
   copying the source(s) under test into the guest via `ndctl=` / `famfs=`.
4. **Streams the guest serial console live** into the Jenkins console (so the
   in-guest build/boot/test output is visible and tailable during the run).
5. Parses a result **sentinel** off the console and gates the build.

Key `call()` args: `kernelRepo`, `kernelBranch`, `configFile`, `autorunScript`,
and at least one of `ndctlSrc` / `famfsSrc`. Optional: `runQemuArgs`,
`timeoutMin`, `kcmdAppend`, `resultSentinel`, `unstableOnFail`. Full list is in
the fixture's header comment.

## run_qemu fork

The fixture defaults to **`git@github.com:jagalactic/run_qemu.git`** branch
**`famfs`**, not upstream `pmem/run_qemu`. The fork carries:

- the build initramfs kept in `$builddir` instead of `mkosi.extra/boot` (so
  mkosi doesn't copy it onto the size-capped 512M ESP and overflow it);
- extra guest rootfs packages for building/testing famfs: `cmake`, `gcc-c++`,
  `fuse3`, `libyaml-devel`, `attr`;
- the **`famfs=<path>`** option (rsync a famfs tree into the guest at
  `/root/famfs`), symmetric to the existing `ndctl=<path>`;
- env-tunable `cxl_t3_size` / `cxl_backend_size` (the cxl smoke job sets
  `cxl_t3_size=8G` for a file-backed CXL type3 device).

## Artifacts

Every build archives:

- **`console.log`** - the full guest serial console.
- **`test-results.txt`** - the extracted meson testlog (per-test detail + summary).
- **`test-summary.txt`** - a compact one-line-per-test `PASS/FAIL/SKIP` list with
  durations and `PASS/FAIL/SKIP` counts (generated by `test-summary.awk`).

## Deploying / updating a job

Each job's entrypoint is `*.groovy` (inline in the job config). The fixture,
autorun scripts, `.config`, and `test-summary.awk` are read live from this repo
at build time, so editing **those** only needs a push; editing an **entrypoint**
needs a redeploy:

```sh
JOB=<job-name> JENKINS_USER=jmg scripts/create-job.sh
```

`create-job.sh` reads the API token from `api-key.md` (gitignored) and derives
the entrypoint file and description from `$JOB`. It also replaces any
`@NOTIFY_EMAIL@` placeholder in the entrypoint with `NOTIFY_EMAIL` from
`site.conf` (gitignored; copy `site.conf.example`).

> **ASCII only** in anything embedded in `config.xml` (entrypoints + the
> description): Jenkins' config-update path decodes the POST body as Latin-1, so
> a non-ASCII char (e.g. an em-dash) becomes invalid XML and the save fails with
> HTTP 500 / "Failed to persist config.xml".

## Concurrency / VM sizing

- Concurrent builds on different executors get distinct host ports/MACs via
  `--instance ${EXECUTOR_NUMBER}` (run_qemu derives the SSH-forward port as
  `10022 + instance`). Per-job workspaces keep the kernel tree / `qbuild` /
  `console.log` isolated.
- vcpus are `num_nodes x cores(2) x threads(2 on KVM)`; pass `--nodes N` in
  `runQemuArgs` to change it (also changes the NUMA layout). No direct `--smp`.
